## Findings sent immediately to the lead

1. **Assertions must not disappear under Python optimization.** Exact toolchain, actual package pins, source cleanliness, source-scan exclusions, negative-calibration reason checks and unchanged pin-file checks are implemented as Python `assert`. Inherited `PYTHONOPTIMIZE` or invocation with `-O` can remove all these checks while the runner still reports success. Replace security/acceptance assertions with explicit raising checks, or fail immediately if `sys.flags.optimize != 0`; clearing the variable only in child processes is insufficient because the runner itself has already started.

2. **A clean Git status does not establish an artifact-free start.** `--require-clean` checks tracked and nonignored source files, while `.lake` is deliberately ignored. The proposed reconstruction must log a startup scan after all source clones and before any Lean/Lake build. Match `*.olean*` including `.olean.private` and `.olean.server`, `*.ilean`, `*.ir`, `*.o`, `*.a`, `*.so` and `*.ltar`. The bundled, verified Lean toolchain is the intended exception; source-pinned ProofWidgets JavaScript and its committed `lake.trace` are not Lean proof artifacts. A cached local runner pass must retain its narrower label and cannot substitute for this start receipt.

3. **Prevent stale successful evidence from surviving an early failure.** The runner accepts an existing evidence directory, but rejects dirty source before constructing and saving its new `passed: false` report. Reusing a directory after that early failure can leave an old `verification.json` with `passed: true`. Require a fresh evidence directory (or at least reject existing final-report files), and initialize the current run record before early acceptance checks where feasible. A new temporary external directory in the planned clean procedure avoids this problem, but the runner should enforce the distinction itself.

4. **Audit the independent expanded-statement consumers.** The runner currently compiles `checks/release/IndependentStatements.lean` as plain Lean even though that file contains axiom reports. Use the fresh axiom checker with its expanded declaration names required, in addition to plain compilation if retained. The current source is mathematically sound and uses the actual public theorems; a required audit prevents a later custom-axiom or placeholder change in these independent consumers from silently reducing the statement gate to mere elaboration.

5. **Freeze the regression coverage and final source identity.** Dynamic globs find the present adverse files, and each discovered audit receives full source-position/coverage validation. However, removal/renaming of an essential file can silently reduce the suite. Preserve an explicit minimum set of required regression paths and essential endpoint names, especially the closed singular/rank-increasing triangle, n5 redundancy, square padding, zero-component scalar failure, pair-frontier failure and nonpositive equality counterexample. At exit compare HEAD/tree and source hashes against their initial values as well as Git cleanliness and pin-file hashes; a clean but changed commit during the run should not be recorded under the original revision.

No false release success was observed; these are source-review findings before the final clean reconstruction. The lead was notified immediately of findings 1–4 rather than waiting for this report.
